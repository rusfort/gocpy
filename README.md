# Gocpy (Go-C-Py) — компилятор

Язык, объединяющий простоту Go, контроль над памятью из C и лаконичность Python.
Компилятор пишется на Go, бэкенд — генерация C, рантайм — на C.

## Статус: этап 1 — фронтенд

| Компонент | Пакет | Статус |
|---|---|---|
| Токены | `internal/token` | готово |
| Лексер (авто-`;`, f-строки, `@`) | `internal/lexer` | готово |
| AST + печать + обход | `internal/ast` | готово |
| Парсер (рекурсивный спуск) | `internal/parser` | готово |
| Ранние проверки `@throws` / `@overload` | `internal/check` | готово (MVP) |
| Проверка типов | `internal/types` | дальше |
| IR и генерация C | `internal/ir`, `internal/codegen/c` | дальше |
| Чтение `.yml`, сборка | `internal/build` | дальше |
| Рантайм (GC, планировщик) | `runtime/` | дальше |

## Сборка и запуск

```sh
go build -o bin/gocpy ./cmd/gocpy
go test ./...

bin/gocpy tokens examples/hello.gocpy
bin/gocpy parse  examples/hello.gocpy
bin/gocpy check  examples/feed
```

## Грамматика

См. `docs/grammar.ebnf`.

## Зафиксированные решения

- Фигурные скобки, без `;` (вставляются лексером, как в Go).
- Статическая типизация + `any`, дженерики, интерфейсы, методы как в Go.
- Числовые типы как в Go (`int64`, `uint8`, ...).
- Ошибки — значения с оператором `?`; исключения — `throw` / `try` / `catch` / `finally`.
- `@throws` обязателен для функций, из которых может вылететь исключение;
  `main` и точки входа горутин не могут быть `@throws`.
- Перегрузка функций и операторов только с `@overload` на каждом варианте.
- `unsafe { }` — `malloc` / `free`, арифметика указателей, приведения.
- Единица компиляции — директория; `gocpy.yml` (модуль) и `<file>.yml` (настройки файла).
- `in` — ключевое слово (`for x in xs`, comprehensions).

## Этап 2: типы и генерация C

- `internal/types` — проверка типов: константы произвольной точности, перегрузка функций и операторов (`@overload`), запрет повторного `:=` в той же области видимости, запрет конфликтов имён с импортами, `in` — ключевое слово.
- `internal/codegen/c` — генерация C (GNU C11), `runtime/c` — рантайм на C (строки, срезы, форматирование, проверки границ), GC — Boehm (`build.gc: boehm|none`).
- `internal/build` — чтение `gocpy.yml` и `<file>.yml` (opt, flags), `native.c/include/link`, `@extern("имя")`.

```
gocpy build [-o out] [-emit-c dir] [-v] <dir|file>
gocpy run examples/stage2
```

## Этап 3: исключения и строгие правила

- `throw X` — X значение именованного типа; `catch e: T` ловит по типу, `catch e` / `catch` — всё (тип `e` — `Exception`: `Message()`, `TypeName()`, `String()`), `throw e` в catch — повторный выброс, `finally` выполняется при любом выходе (обычном, исключении, `return`, `break`, `continue`).
- `@throws` проверяется точно, по разрешённым вызовам (с учётом перегрузок и методов): исключение не может покинуть функцию без `@throws`; `@throws` без выбросов — ошибка; вызовы `@throws` в инициализаторах пакета запрещены; `return/break/continue` не могут покидать `finally`.
- Реализация без setjmp/longjmp: `throw` пишет `gocpy_exc` и делает `goto` к обработчику, после вызова `@throws`-функции — одна проверка `GOCPY_PENDING()`.
- Затенение запрещено полностью (включая встроенные имена вроде `len`, `int`).
- Неиспользуемые локальные переменные — ошибка; подавление: `x := f() //gocpy:ignore:unused` (директива на той же строке).

- Встроенное исключение в стиле Java: `throw Exception("сообщение")`; `catch e: Exception` — то же, что `catch e`.

## Этап 4: горутины и каналы

- `go f(args)` и `go obj.Method(args)`: аргументы вычисляются в текущей горутине; точка входа не может быть `@throws`.
- `chan T`, `make(chan T)` / `make(chan T, n)`, `ch <- v`, `<-ch`, `v, ok := <-ch`, `close(ch)`, `len`/`cap`, `for v in ch`.
- `select` с `default`, отправкой и приёмом (`case v := <-ch`, `case v, ok := <-ch`, `case ch <- v`, `case <-ch`); `break` выходит из select.
- `std/sync`: `WaitGroup` (`Add`, `Done`, `Wait`), `Mutex` (`Lock`, `Unlock`); нулевое значение готово к использованию.
- `std/time`: `Duration`, `Nanosecond` … `Hour`, `Sleep`, `Now`, `Since`, `d.Milliseconds()`, `d.Seconds()`.
- Ошибки рантайма как в Go: `send on closed channel`, `close of closed channel`, `all goroutines are asleep - deadlock!` (код 2).
- Реализация MVP: горутина = поток pthread (зарегистрирован в Boehm GC), исключения — на поток; каналы/WaitGroup/Mutex используют одну блокировку рантайма. Проверено ThreadSanitizer и ASan.

Ещё не поддерживается: unsafe/malloc (этап 5), defer, дженерики, интерфейсы, `any`, map, замыкания (в том числе `go func(){...}()`), `.go` файлы в модуле.

## Этап 5: замыкания, defer, map, интерфейсы

- Функциональные значения `func(...)`, литералы функций и замыкания. Захваченные переменные переносятся в кучу, поэтому замыкание видит последующие изменения.
- `defer` вызывает функции, методы, функциональные значения, методы интерфейсов и `close`. Аргументы вычисляются в момент `defer`, вызовы выполняются в порядке LIFO, в том числе при исключении. Отложенная функция может менять именованные результаты.
- `map[K]V`:
  - литералы, `make`, `delete`, `len`, `v, ok := m[k]`;
  - итерация в порядке вставки;
  - ключи могут быть структурами и массивами;
  - запись в nil-map завершает программу аварийно (abort с кодом 2).
- Интерфейсы реализуются структурно, как в Go: встраивание, `any`, `error`, утверждения типа `x.(T)` и `x.(T)` с `ok`, `switch v := x.(type)`.
- Ошибки и исключения:
  - `errors.New`, оператор `?` для раннего возврата ошибки;
  - `throw err` для значения-ошибки;
  - `catch e: error` ловит любое исключение, реализующее `error`, включая `Exception`.

Ограничения:
- `defer fmt.Println(...)` не поддерживается, нужно обернуть вызов в `func(){...}()`;
- интерфейсы нельзя использовать как ключи map;
- переменная C-подобного `for` общая для всех итераций, а не своя на каждую;
- `fmt` печатает map в порядке вставки;

## Этап 6: дженерики и method values

- Дженерик-функции и дженерик-типы с методами: `func Map[T, U any](...)`, `type Stack[T any] struct {...}`, `func (s *Stack[T]) Push(x T)`.
- Ограничения:
  - `any` и `comparable`;
  - интерфейсы с методами;
  - объединения `int | float64` и `~int`, в том числе именованные: `type Number interface { ~int | ~float64 }`.
  - Интерфейс-ограничение нельзя использовать как обычный тип.
- Вывод аргументов типа из аргументов вызова идёт по структуре (`[]T`, `map[K]V`, `*T`, `func(T) U`, `List[T]`). Нетипизированные константы получают тип по умолчанию, при этом выигрывает более широкий вид, поэтому `Max(2.5, 1)` даёт `float64`. Аргументы можно указать явно: `Max[float64](1, 2)`.
- Реализация — мономорфизация, как шаблоны: для каждого набора аргументов объявление клонируется и проверяется с конкретными типами. Ошибки в теле указывают инстанс: `(in instance Bad[string])`. Бесконечная рекурсия инстанцирования ограничена 64 инстансами.
- Method values `x.M`:
  - получатель вычисляется и копируется в момент взятия значения;
  - для pointer-методов берётся адрес, получатель должен быть адресуемым;
  - работают и методы интерфейсов.

Ограничения:
- тело дженерика проверяется только при инстанцировании, поэтому ошибки в ни разу не использованном дженерике не выявляются;
- у методов не может быть собственных параметров типа (как в Go);
- нет частичного явного указания аргументов типа (`F[int]` при двух параметрах);
- нет method expressions (`T.M`).

## Этап 7: unsafe, malloc и free

Внутри `unsafe { ... }` доступны ручная память, арифметика указателей и приведения указателей. Вне блока эти имена не существуют: `malloc is only available inside an unsafe block`. Обычное имя `free` в остальном коде остаётся свободным.

- Память:
  - `malloc(n)` и `calloc(n)` (обнулённая) возвращают `*byte`;
  - `realloc(p, n)`, `free(p)`; `free(nil)` допустим;
  - `memcpy(dst, src, n)` (безопасен при перекрытии) и `memset(p, b, n)`;
  - `slice(p, n)` даёт `[]T` поверх сырой памяти.
- Указатели:
  - `p + n`, `n + p`, `p - n`, `p += n`, `p++` (с шагом в элементах);
  - `p - q` даёт `int`;
  - `<`, `<=`, `>`, `>=`;
  - `p[i]` без проверки границ.
- Приведения `*T ↔ *U` и `*T ↔ uintptr`. Цель `*T` допустима, только если `T` не содержит GC-указателей (числа, bool, массивы и структуры из них). Так соблюдается правило «в malloc-памяти не храним указатели на GC-объекты».
- `defer free(p)` разрешён (как `defer close(ch)`). Аргумент вычисляется в момент `defer`; если блок может переехать через `realloc`, используйте `defer func() { free(p) }()`.
- `@be_to_le(x)` и `@le_to_be(x)` разворачивают порядок байт целых, float, массивов и структур из них, включая `@packed`. Эти интринсики работают и вне `unsafe`.
- Рантайм завершает программу с кодом 2 при OOM, отрицательном размере и `free`/`realloc` GC-памяти (при `gc: boehm`). Двойной `free` и use-after-free остаются UB, как в C; ловите их через ASan.

## Установка

Готовые бинарники для linux/darwin (amd64, arm64) выкладываются в GitHub Releases. Варианты установки: `brew install --cask rusfort/tap/gocpy`, `curl -fsSL .../install.sh | sh`, пакеты `.deb`, `.rpm`, `.apk` или `go install`. Подробности и порядок публикации описаны в [docs/RELEASE.md](docs/RELEASE.md).

Для сборки программ нужны gcc или clang и libgc. Проверка окружения: `gocpy doctor`.
