# Модули и зависимости (Gocpy 0.2.0)

Импорты в `.gocpy` работают как в Go, а версии зависимостей задаются в `gocpy.yml`, по аналогии с `go.mod`. Зависимости бывают двух видов: модули на Gocpy и модули на Go.

## gocpy.yml

```yaml
module: github.com/rusfort/gocpy-first-app
version: 0.1.0
build:
  opt: 2
  gc: boehm
require:
  gocpy:
    - github.com/john/gocpy-repo@v0.1.0
  go:
    - github.com/bob/go-repo@v0.2.0
replace:                      # необязательно, действует только в главном модуле
  github.com/john/gocpy-repo: ../gocpy-repo     # локальная копия
  github.com/bob/go-repo: ../go-repo            # локальная копия Go-модуля
```

- `module` — путь модуля. Он же префикс путей импорта его пакетов: `github.com/rusfort/gocpy-first-app/util` — это каталог `util/`.
- `require.gocpy` — модули с исходниками на Gocpy, в их корне должен лежать `gocpy.yml`.
- `require.go` — обычные Go-модули, они подключаются через мост в Go (подробности ниже).
- Версия записывается в формате semver с `v`: `v0.1.0`, `v1.2.3-rc.1`.
- Один модуль нельзя указать дважды или сразу в обоих разделах.
- Старая плоская форма из 0.1 (`require: {path: version}`) по-прежнему читается как `require.gocpy`.
- `replace` подменяет модуль локальным каталогом. Для Go-модулей можно также указать `другой/путь@версия`.

## Импорты

```gocpy
import (
    "std/fmt"                                       // стандартная библиотека
    "github.com/rusfort/gocpy-first-app/util"       // пакет своего модуля
    "github.com/john/gocpy-repo/geo"                // пакет Gocpy-зависимости
    gr "github.com/bob/go-repo"                     // Go-пакет, с псевдонимом
)
```

Правила:
- Пакет — это каталог с файлами `.gocpy`, по одному пакету на каталог. Пакет `main` импортировать нельзя.
- Имя импорта по умолчанию — это имя пакета из его исходников, а не последний элемент пути.
- Снаружи видны только имена с заглавной буквы. Это касается и полей, и методов: `p.tag` из другого пакета даёт ошибку.
- Конфликт имён импорта запрещён: два пакета `geo` в одном файле требуют псевдонима. Запрещено и затенение имени импорта локальной переменной.
- Неиспользуемый импорт — ошибка.
- Циклы импортов и относительные пути (`./util`) запрещены.

Между пакетами работает всё: типы, методы, дженерики (инстанцируются в месте использования), интерфейсы, исключения (`catch e: geo.ParseError`, `@throws(geo.ParseError)`), константы и глобальные переменные. Пакеты инициализируются в порядке зависимостей.

## Gocpy-зависимости

- Модуль `github.com/john/gocpy-repo@v0.1.0` загружается командой `git clone --depth 1 --branch v0.1.0`.
- Модуль из подкаталога репозитория (`github.com/john/mono/lib`) берётся по тегу `lib/v0.1.0`, как в Go.
- Кэш хранится в `$GOCPY_MODCACHE`, а по умолчанию в `~/.cache/gocpy/mod` (на macOS — `~/Library/Caches/gocpy/mod`).
- Приватные репозитории работают через обычную настройку git: ssh-ключи, credential helper, `url.<base>.insteadOf`.
- Выбор версий идёт по MVS, как в Go: если `other` требует `gocpy-repo@v0.2.0`, а главный модуль — `v0.1.0`, то будет выбрана `v0.2.0`.
- Нативный C-код зависимостей (`native.c`, `native.include`, `native.link` в их `gocpy.yml`) собирается вместе с программой.

### gocpy.sum

- При первой загрузке хеш модуля (`h1:`, тот же алгоритм, что в `go.sum`) записывается в `gocpy.sum` рядом с `gocpy.yml`.
- При следующих сборках хеш сверяется. Если содержимое тега изменилось, сборка останавливается с ошибкой `SECURITY ERROR: checksum mismatch`.
- В этот же файл попадают строки Go-модулей (формат `go.sum`), и они проверяются тулчейном Go.
- `gocpy.sum` нужно коммитить в git вместе с `gocpy.yml`.

## Go-зависимости (мост в Go)

```gocpy
import (
    "std/fmt"
    "github.com/google/uuid"
)

func main() {
    fmt.Println(uuid.NewString())
    if err := uuid.Validate("nope"); err != nil {
        fmt.Println(err)
    }
}
```

Нужен установленный Go 1.21 или новее. Путь к нему можно задать через `GOCPY_GO`, проверить окружение — командой `gocpy doctor`. Сборка устроена так:
1. Для импортированных Go-пакетов создаётся служебный Go-модуль с `require` и `replace` из `gocpy.yml`.
2. API этих пакетов читается тулчейном Go пользователя.
3. Для каждой поддерживаемой функции генерируются cgo-экспорт, C-адаптер и Gocpy-заглушка.
4. Всё собирается через `go build -buildmode=c-archive` и линкуется в программу.
5. Результат кэшируется в `$GOCPY_CACHE/gobridge`, а по умолчанию в `~/.cache/gocpy/gobridge`.

Поддерживается в 0.2.0:
- функции пакета, у которых параметры и результаты имеют типы `bool`, `int*`, `uint*`, `uintptr`, `float32`, `float64`, `string`, `[]byte`, включая именованные типы с такой основой (например, `time.Duration`);
- необязательный последний результат `error`: он превращается в Gocpy-значение `error`;
- константы этих типов.

Как устроены вызовы:
- Строки и `[]byte` копируются в обе стороны, так что Go не хранит указатели на память Gocpy.
- Вызовы Go выполняются в отдельном пуле потоков, о котором не знает Boehm GC, а вызывающая горутина ждёт в `GC_do_blocking`. Один вызов стоит порядка единиц микросекунд.
- Паника в Go завершает программу с кодом 2: `runtime error: panic in Go code: ...`.

Пока не поддерживается:
- Go-типы, методы, переменные пакета;
- variadic- и generic-функции;
- срезы, кроме `[]byte`;
- map, каналы, функции как значения, обратные вызовы из Go в Gocpy.

При обращении к такому имени компилятор объясняет причину, например: `gr.Join: parameter 1 has type []string, which the Go bridge does not support yet`.

## Команды

```sh
gocpy init github.com/you/app        # gocpy.yml и main.gocpy
gocpy get github.com/john/gocpy-repo@v0.1.0
gocpy get github.com/google/uuid      # без версии — @latest; вид модуля определяется сам
gocpy get -go github.com/bob/go-repo@v0.2.0
gocpy mod download                    # скачать всё, обновить gocpy.sum
gocpy mod verify                      # сверить кэш с gocpy.sum
gocpy mod graph                       # граф требований и выбранные версии
```

`gocpy get` сохраняет комментарии и форматирование `gocpy.yml`. Если модуль уже указан, команда меняет его версию, а плоскую форму из 0.1 переводит в разделы `gocpy:` и `go:`.

## Как опубликовать Gocpy-библиотеку

1. В корне репозитория создайте `gocpy.yml` с `module: github.com/you/lib`. Путь должен совпадать с адресом репозитория.
2. Разложите пакеты по каталогам (`geo/geo.gocpy` → импорт `github.com/you/lib/geo`).
3. Поставьте тег и отправьте его: `git tag v0.1.0 && git push origin v0.1.0`.
4. Пользователи подключают библиотеку командой `gocpy get github.com/you/lib@v0.1.0`.
